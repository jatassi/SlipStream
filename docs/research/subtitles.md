## Answer in brief

- Bazarr's settings UI offers 63 providers. Eight are hosted JSON APIs with a credential: OpenSubtitles.com, SubDL, SubSource, Subs.ro, Jimaku, BetaSeries, Assrt and SubX. Thirty-three scrape HTML. Six need browser cookies or a paid captcha-solving service.
- OpenSubtitles.com uses two credentials. The application holds one consumer `Api-Key`, and each user logs in for a JWT. Requests are limited to 5 per second per IP. Downloads are capped per user: 20 a day for a signed-up account and 1000 for VIP. The archived terms say "Commercial use prohibited."
- ffsubsync (MIT) marks speech in 10 ms windows, using a voice activity detector (VAD) on the audio and cue on/off times on the subtitles. It then finds the best global offset by FFT cross-correlation, with a framerate-ratio search. Since 0.5.1 it also has an alass-style piecewise mode. Its pinned `auditok==0.1.5` dependency is GPLv3.
- alass (GPL-3.0) aligns time spans by dynamic programming with a split penalty. It corrects offsets, mid-file breaks and framerate ratios. Its last release was in 2019.

### Rate limits and throttling in Bazarr

Bazarr turns provider errors into per-provider cooldowns (`bazarr:bazarr/app/get_providers.py` lines 68 to 140). The defaults:

| Error | Cooldown |
|---|---|
| TooManyRequests | 1 hour |
| DownloadLimitExceeded | 3 hours |
| ServiceUnavailable | 20 minutes |
| APIThrottled | 10 minutes |
| ParseResponseError | 6 hours |
| Timeouts and proxy errors | 1 hour |
| ConfigurationError, PermissionError, AuthenticationError | 12 hours |

Per-provider overrides exist for OpenSubtitles.com, Addic7ed, Titlovi, Titrari, Titulky, LegendasDivx, Whisper, RegieLive, SubSource and SubDL. For example, OpenSubtitles.com uses 1 minute for TooManyRequests and 6 hours for DownloadLimitExceeded. Titulky, LegendasDivx and SubDL compute the cooldown as the time until their quota resets.

A shared HTTP layer also parses `Ratelimit`, `Ratelimit-Policy` and `X-RateLimit-*` response headers to pace requests (`bazarr:custom_libs/subliminal_patch/global_rate_limiter.py`, used from `http.py` line 24).

## 2. OpenSubtitles.com

### Authentication and keys

The facts below come from [Getting started](https://opensubtitles.stoplight.io/docs/opensubtitles-api/e3750fd63a100-getting-started).

- Two mechanisms apply. A static consumer API key identifies the application and goes in the `Api-Key` header. A JWT identifies the user and goes in `Authorization: Bearer`.
- Use one key per application. The docs warn that if an application makes its users create their own API key, OpenSubtitles "will ban their access." Wrappers are the exception.
- Developers create keys in the "API consumers" section of their opensubtitles.com profile.
- A user must be authenticated for `/infos/user` and `/download`.
- A JWT is valid for 24 hours.
- Every request needs a `User-Agent` of the form `AppName vX.Y`. A bad one returns 403 ([Best-Practices](https://opensubtitles.stoplight.io/docs/opensubtitles-api/6ef2e232095c7-best-practices); [Changelog](https://opensubtitles.stoplight.io/docs/opensubtitles-api/51ea4c484e6e5-changelog), 8 September 2023).
- `/login` returns a `base_url` to use for later requests (Changelog, 16 February 2023). The servers are `api.opensubtitles.com/api/v1` and `vip-api.opensubtitles.com/api/v1` ([API overview](https://opensubtitles.stoplight.io/docs/opensubtitles-api/b1eb44d4c8502-open-subtitles-api)).
- The docs ask developers to contact OpenSubtitles when they release an app, so it can be added to their database.

Bazarr follows this model. It embeds one consumer key in source (`bazarr:bazarr/app/get_providers.py` line 261) and asks each user for a username and password. It caches the token for 12 hours (`bazarr:custom_libs/subliminal_patch/providers/opensubtitlescom.py` line 32). It switches to the `base_url` from login and adds the Bearer header only when that host starts with `vip` (same file, lines 214 to 247).

### Rate limits and download quotas

- Requests are limited to 5 per second per IP. Going over returns 429 ([Best-Practices](https://opensubtitles.stoplight.io/docs/opensubtitles-api/6ef2e232095c7-best-practices)).
- `/login` is limited to 1 request per second. The docs say to stop retrying a user whose login fails.
- Responses carry `ratelimit-limit`, `ratelimit-remaining`, `ratelimit-reset` and `x-ratelimit-*-second` headers.
- Search is unlimited. Only downloads are limited.
- Without a logged-in user, a consumer gets 5 downloads per IP per 24 hours.
- A signed-up user gets 20 downloads a day and a VIP user gets 1000.
- A consumer marked "Under Development" gets up to 100 downloads a day without user authentication, as a temporary allowance.
- Getting started says "Download counters resets at midnight UTC time." The [Error codes](https://opensubtitles.stoplight.io/docs/opensubtitles-api/12f131ce12132-error-codes) example instead shows a quota that renews 23 hours 57 minutes after the last download, at a non-midnight UTC time. The two sources conflict.
- A download is counted when `/download` is requested, not when the file is fetched. The returned link lasts 3 hours ([Download](https://opensubtitles.stoplight.io/docs/opensubtitles-api/6be7f6ae2d918-download)).
- The `/download` response includes `requests`, `remaining`, `reset_time` and `reset_time_utc`. A 406 response means the quota is exceeded. Bazarr maps that 406 to DownloadLimitExceeded (`opensubtitlescom.py` lines 569 to 581).

### Endpoints SlipStream would touch

- `GET /subtitles` searches by `imdb_id`, `tmdb_id`, `parent_imdb_id` with `season_number` and `episode_number`, `moviehash`, or `query`. Filters include `languages`, `hearing_impaired`, `foreign_parts_only`, `ai_translated` (default include) and `machine_translated` (default exclude) ([Search for subtitles](https://opensubtitles.stoplight.io/docs/opensubtitles-api/a172317bd5ccc-search-for-subtitles)).
- Results matching a moviehash come first and carry `moviehash_match`.
- Send parameters sorted alphabetically and in lowercase, with leading zeros stripped from IDs. Otherwise the API redirects.
- `POST /download` takes `file_id` and returns a temporary link. It can convert the format (`sub_format`), convert framerate (`in_fps`, `out_fps`) and shift timing (`timeshift`, in seconds).
- Downloaded files are UTF-8 SRT by default.
- The docs ask clients to call `/logout` when finished.

### Moviehash

The hash is the file size plus a 64-bit sum of the first and last 64 KiB, read as little-endian 64-bit words. The result is zero-padded to 16 hex characters. Files must be between 131072 and 9000000000 bytes. The [Hash Source Codes](https://opensubtitles.stoplight.io/docs/opensubtitles-api/4wccbf76rim38-hash-source-codes) page gives two test vectors: `breakdance.avi` hashes to `8e245d9679d31e12`, and the unpacked `dummy.rar` file hashes to `61f7751fc2a72bfb`.

## 3. Other providers with a documented API

### SubDL

The facts below come from [subdl.com/api-doc](https://subdl.com/api-doc).

- A `client` parameter identifies the integration. Its listed values include `bazarr`.

## 4. Timing sync

### ffsubsync

**Algorithm.** The facts below come from `ffs:README.md`, "How It Works", line 280 onward.

1. Discretize the audio and the subtitles into 10 ms windows (`SAMPLE_RATE = 100`, `ffs:ffsubsync/constants.py` line 7).
2. Mark each window as speech or not. For subtitles, a window is speech when a cue is showing. For audio, a VAD decides.
3. Score each alignment of the two binary strings. The score is the video speech windows matched with subtitle speech windows, minus the video speech windows matched with subtitle silence. The best score is computed by FFT, so all offsets are scored in O(n log n) (`FFTAligner`, `ffs:ffsubsync/aligners.py` line 24).

**Framerate.** By default ffsubsync also tries the scale ratios 24/23.976, 25/23.976 and 25/24 (`FRAMERATE_RATIOS`, `constants.py` line 9). With `--gss` it searches the ratio by golden-section search instead. `--no-fix-framerate` turns ratio correction off.

**Defaults.** The maximum offset is 60 s (`DEFAULT_MAX_OFFSET_SECONDS`, line 18). The default VAD is `subs_then_webrtc` (line 17). That means: use embedded subtitles in the reference file if present, otherwise WebRTC.

**VAD choices** (`ffs:README.md`, "Sync Issues", lines 214 to 256):

- `webrtc` is the default.
- `auditok` detects any audio rather than speech specifically.
- `fused` combines WebRTC with the neural Silero VAD. It needs PyTorch, and it loads the model through `torch.hub` from the `snakers4/silero-vad` GitHub repository at runtime (`ffs:ffsubsync/speech_transformers.py` lines 208 to 213). Inferred: that is a network fetch the first time.
- `--whisper-weights` transcribes the audio with whisper.cpp through an ffmpeg (8.0 or later) built with `--enable-whisper`, and uses the transcript as the reference.

**References.** The reference can be a video, an audio file, another subtitle file, an embedded subtitle stream (`--reference-stream`) or a PGS image subtitle stream (0.5.0). It can also be a remote URL (0.5.0) (`ffs:HISTORY.rst` lines 9 to 24).

**Mid-file breaks.** The default aligner emits one global offset. The README says this covers ">95% of use cases" (`ffs:README.md`, "Limitations", line 303). Release 0.5.1 added `--split-penalty`. The module calls it an "alass-style split-penalty alignment." It is a dynamic program over cues and offsets, `O(n_cues * n_offsets)`, written in pure numpy (`ffs:ffsubsync/split_aligner.py` lines 1 to 44). The README calls it experimental.

**Quality gate.** Since 0.5.0, `--skip-sync-on-low-quality` leaves the subtitles unchanged when the alignment looks untrustworthy. The thresholds are `--min-score` (default 0.0), `--quality-max-offset-seconds` (default 30) and `--max-framerate-deviation` (default 0.1) (`ffs:README.md` line 258 onward).

### alass

**Algorithm.** The facts below come from `alass:README.md` and `alass:alass-core/src/lib.rs`.

- alass works on time spans, not on sampled windows. For a video reference, it runs WebRTC VAD on the audio extracted by `ffmpeg` and turns the result into spans (`alass-cli/src/lib.rs` line 258 onward). For a subtitle reference, it uses the cue spans directly.
- `align()` gives each incorrect span its own delta. It maximizes the overlap rating minus a split penalty for each change in delta (`lib.rs` lines 103 to 130). The penalty runs from 0 to 1000. Useful values are 4 to 20, and the optimum is "7+-1." A value of 1000 forces one global offset.
- `--no-splits` uses only the fast single-offset path, `align_nosplit`.
- The thesis (`alass:documentation/thesis.pdf`) gives the complexity. It brings the no-split search to O(KN log min(K, N)) and the split case to O(KN log(KN)) worst case, for K and N spans. The figures come from the pdftotext extraction of the thesis, section 2.5 onward.
- **Framerate.** It tests the six ratios among 25, 24 and 23.976 fps and keeps the best (`alass:alass-cli/src/main.rs` lines 366 to 381). `--disable-fps-guessing` turns this off.
- **Formats.** It accepts `.srt`, `.ssa`/`.ass` and `.idx` subtitles, and any video format ffmpeg reads.
- **Language.** The README calls it "language-agnostic." It can align subtitles to a reference in another language.

**Reported accuracy** (`alass:README.md`, "Performance and Results", line 65). These are the author's own measurements, not reproduced here.

- Audio extraction takes 10 to 20 s and alignment takes 5 to 10 s.
- On N=118 random OpenSubtitles.org files, about 50% were out of sync before alignment.
- After alignment, 50% of lines were within 50 ms, 80% within 100 ms, 90% within 400 ms and 95% within 800 ms.

**License and maintenance.**

- alass is GPL-3.0 (`alass:LICENSE`). Both `alass-core` and `alass-cli` declare `license = "GPL-3.0"` in their Cargo.toml.
- `alass-core` has no dependencies. It exposes a Rust library API, `align` and `align_nosplit`.
- The last release, v2.0.0, came out on 2019-10-10. The last commit on the default branch is from 2021-04-11, and the last push to the repository was on 2023-12-28. It has 36 open issues and is not archived (GitHub API).

### How Bazarr wires sync

- Bazarr vendors ffsubsync 0.5.0 and auditok 0.1.5 (`bazarr:libs/`). It calls ffsubsync in process (`bazarr:bazarr/subtitles/tools/subsyncer.py`).
- It uses `subs_then_webrtc` when `webrtcvad` imports and falls back to `subs_then_auditok` otherwise (lines 29 to 34).
- It always passes `--max-offset-seconds` and `--output-encoding same`. It adds `--gss` and `--no-fix-framerate` per settings. When framerate fixing is on, it adds the quality gate flags (lines 147 to 160).
- A reference stream can be forced to an audio track or a subtitle track. It can also be chosen by matching the media's original language (lines 166 to 198).
- There is no alass integration in the tree.
- **Trigger.** Sync runs after a download when `use_subsync` is on. Separate series and movie thresholds can restrict it to subtitles whose match score is at or below a percentage, defaulting to 90 for series and 70 for movies (`bazarr:bazarr/subtitles/sync.py` lines 47 to 53, `bazarr:bazarr/app/config.py` lines 441 to 461). Inferred intent: a hash-matched, high-score subtitle is assumed to be in sync already.
- **Defaults** (`config.py` lines 441 to 461): `no_fix_framerate` true, `gss` true, `max_offset_seconds` 60, `quality_min_score` 0.0, `quality_max_offset_seconds` 30, `quality_max_framerate_deviation` 0.1.
- A checker can skip sync for listed providers and languages.

## 5. Options for the decision

These are options and tradeoffs, not a recommendation. Lines marked "inferred" are reasoning, not sourced facts.

### Providers

1. **Native providers for the JSON APIs only.** That means OpenSubtitles.com, SubDL, SubSource, and optionally Jimaku, Subs.ro and Subtis. Each has a stable, documented contract with explicit limits. HTML scrapers, cookie and captcha providers would stay out. Inferred: this loses most single-language regional catalogs, such as the Greek, Bulgarian, Romanian and Hebrew sites.
2. **Native port of a wider Bazarr set.** Covers the regional catalogs. Inferred: scrapers break when sites change. Bazarr's own list carries several "broken" or stub entries. The `subliminal_patch` code is GPL-3.0 by repository license, so copying it would bring GPL obligations. Writing from the behavior, rather than the code, would not.
3. **Run Bazarr or subliminal beside SlipStream** as a sidecar, through Bazarr's API. This keeps the whole catalog. Inferred: it brings in a Python runtime and a second database. It also conflicts with the Q15 framing of built-in subtitles.

OpenSubtitles.com constraints that apply to any option:

- SlipStream would register one consumer key and ship it, as Bazarr does. Users would log in with their own accounts.
- At 20 downloads a day for a free account, the user's account sets the daily ceiling, not SlipStream.
- The free consumer tier puts ads in the subtitle files. Removing them costs from 20 USD a month.
- The archived terms prohibit commercial use. Inferred: that matters only if SlipStream is ever sold or hosted for others.

Offline mode (Q17), inferred: every provider here is a network service. The offline end-to-end suite would need a fake provider behind the same contract, and the moviehash test vectors above give a fixture-ready check for the hash function.

### Timing sync

1. **Run ffsubsync as a subprocess.** It is the most active and most featureful choice, and MIT at the top level. Costs: it bundles a Python runtime in packages and Docker images (Q24). The `auditok==0.1.5` pin is GPLv3. ffsubsync imports auditok lazily, only when an auditok VAD is selected. Its own error text warns that importing it "creates a derivative work that is GPLv3 licensed" (`ffs:ffsubsync/speech_transformers.py` lines 104 to 125). Inferred: a build that omits auditok and uses the WebRTC VAD avoids it. The `fused` VAD needs PyTorch and fetches a model over the network.
2. **Run alass as a subprocess.** It is a single static Rust binary and strong on mid-file breaks. Costs: GPL-3.0 and unmaintained since 2019 to 2021. Inferred: calling a separate GPL program over its command line is the usual "aggregate" pattern, not a derived work. Confirm with whoever owns licensing.
3. **Reimplement in SlipStream's stack.** The ffsubsync method is short: a 10 ms speech bitmap, FFT cross-correlation and a ratio search. It is described in its README and in MIT code, so porting it is unencumbered. The alass split DP is documented in the thesis, and ffsubsync already reimplemented it under MIT. A VAD is needed. libfvad, the standalone WebRTC VAD in C, is BSD-3-Clause (GitHub API, [dpirch/libfvad](https://github.com/dpirch/libfvad)). Inferred: this is the only option with no Python or GPL dependency, at the cost of owning the algorithm and its tuning.

The ffmpeg dependency is shared with the A/V pipeline (Q14) in every option. Inferred: audio extraction for sync could be scheduled as a Role job on whichever Node holds the file.
