# Transfers are receiver-driven chunk copies between Nodes

Every file copy between Nodes is a Transfer, whether it carries a completed download, a Conversion's input or output, or a Move. Release files travel on the frozen update path (ADR 0015) and the Handover archive over the Node link (ADR 0018), so neither is a Transfer. The Controller records each Transfer and tells both Nodes about it through their intent. The two Nodes open extra TLS connections with the keys pinned at Pairing, dialed by the receiver, or by the sender when the receiver can't reach it. If neither can reach the other, the Transfer runs over the Node link when one end is the Controller, and through a Relay Node once S52 (Relay Node) adds relayed Transfers. Until then, two Workers that can't reach each other wait. The receiver asks for chunks over those connections, and the sender hashes each chunk with BLAKE3 as it reads it and sends the hash with the chunk. TLS already rejects bytes changed in flight. The hash catches memory faults between the sender's read and the receiver's write, and stale or misplaced staged data on resume. The source's own integrity rests on the Download Client's completion check. The receiver checks every chunk before it writes it. After it syncs each batch, it reads the batch back and checks it again, to catch a bad write to staging. It resumes from the chunks it has verified, and restarts a file from zero when the source file changed or the record of verified chunks is lost. The receiver stages files on the destination's filesystem until import takes each Item of a download, or until a Move switches its whole Work over (ADR 0016). A remote seedbox running an external Download Client needs a SlipStream Worker on it, since no Transfer reaches files without a Node.

Charting Q11 called this a push. The data still flows to the importing Node without a person starting it, but the receiver drives the copy, because every fast tool that splits one file across connections does it as a pull. Decided in [File sync design](https://github.com/jatassi/SlipStream/issues/14#issuecomment-5988990718), Q2, Q5, Q6, Q8 and Q12, and [Transfers between Nodes](https://github.com/jatassi/SlipStream/issues/156), which replaced Q12's rehash of staged files with a restart.

## Considered Options

- **Sender-driven push with offset writes.** Rejected. It needs a receiver that accepts writes at any offset and a second resume design, and buys nothing the receiver-driven form lacks.
- **HTTPS range pull by the storage Node.** Rejected. The sender must accept inbound connections, which fails when the seedbox is the side that dials out.
- **rclone or lftp over SFTP.** Rejected. Segmenting works only as a pull, SFTP pipelines cap one file at roughly 40 to 170 Mbit/s at 100 ms by default (computed in [Fast transfer between Nodes](https://github.com/jatassi/SlipStream/issues/13)), and it means a second binary to ship.
- **BitTorrent between Nodes.** Rejected. BEP 27 forbids peers outside the tracker for private torrents.
- **Torrent piece hashes as the integrity reference.** Rejected. A v1 piece can span two files, and external clients and derived files offer no piece hashes.
- **A Node-less SFTP path for remote seedboxes.** Rejected. It brings back the SFTP ceiling and a second resume and verification design. A seedbox host that forbids user processes is the accepted cost.

## Consequences

- Each new kind of job that moves files names only what to copy, where, and what happens after. Resume, verification, bandwidth caps and the offline fakes stay in one place.
- A Transfer picks its own dial direction, because two Workers have no Node link between them to copy one from. The Node link carries a Transfer only as the last route between a Worker and the Controller. A Relay Node will carry bulk file traffic as well as calls once S52 (Relay Node) adds relayed Transfers. Decided in [Transfers between Nodes](https://github.com/jatassi/SlipStream/issues/156).
- Import of a download works per Item from a staging folder on the library root's filesystem, and its placement decision runs before the Transfer starts. Decided in [Moving torrents and library files between Nodes](https://github.com/jatassi/SlipStream/issues/90), Q5.
