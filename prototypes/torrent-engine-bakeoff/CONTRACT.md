## Fixtures

`fixtures` binary: `gen --out DIR --count N --piece-len 4194304 --pieces 1024 --announce URL [--announce-list 'A1,A2;B1,B2'] [--name-prefix p]`.

- Writes `DIR/torrents/<name>.torrent` and `DIR/data/<name>` (one single-file torrent each, sparse via truncate, all zero bytes, so every piece hash is SHA-1 of a zeroed piece computed once).
- `private=1`. Names are unique, so infohashes are unique.
- `--announce-list` uses `;` between tiers and `,` within a tier. When given, it also sets `announce` to the first URL.
- Writes `DIR/manifest.json`: `[{"name","infohash","torrent","data","size"}]`.

## Tracker

`tracker --log FILE --interval S --min-interval S [--listen 127.0.0.1:7070,127.0.0.1:7071,...] [--fail-infohash HEX,...] [--enforce]`

- HTTP only. Path `/<passkey>/announce`. Compact peer lists. Returns `interval`, `min interval`, `complete`, `incomplete`, `peers`.
- Keeps an in-memory swarm per infohash (peer ip/port/left, expiring after 2x interval), so engines can find each other: this is the fake swarm.
- UNIT3D-style rules, recorded on every announce and enforced (returned as `failure reason`) only with `--enforce`:
  - Both rules follow UNIT3D's `checkMinInterval` (`AnnounceController.php` at `8b88f4c`); `tracker/NOTES.md` has the exact semantics.
  - `duplicate_event_30s`: the same event (empty counts as one) within 30 s of the first one.
  - `min_interval_violation`: any announce other than `completed` or `stopped` inside 0.9 x min interval of the announce that opened the window.
  - `--fail-infohash`: always answer those infohashes with `failure reason: "fake failure"`.
- Log: one JSON object per line, `{"t": unix_float, "listener": "127.0.0.1:7070", "path", "passkey", "infohash": hex, "peer_id": raw-as-escaped-string, "peer_id_hex", "ua": User-Agent, "event": "", "uploaded", "downloaded", "left", "port", "numwant", "violations": [..], "rejected": bool}`.

## Engine harnesses

Each harness is one binary. Shared flags:

- `--mode seed|lifecycle`
- `--fixtures DIR` (reads `manifest.json`)
- `--listen-port P`
- `--peer-id-prefix STR` (optional; default is the engine's own)
- `--status FILE`: append JSON lines `{"t", "event", ...}` for milestones (`all_added`, `step`, `error`).

Every harness disables DHT, LSD/local discovery, PEX for private torrents (BEP 27 does this anyway), UPnP/NAT-PMP, and every limit on how many torrents may be active, so all torrents seed and announce at once. Use the engine's defaults for everything else, then apply the tuning a production seedbox build would use and say which settings in your NOTES.md.

### `--mode seed`

Add every torrent in the manifest as a complete seed **without hashing the data** (libtorrent `seed_mode`, anacrolix a piece-completion store that reports every piece complete, rain whatever is cheapest; say what you did). Write `all_added` with the elapsed seconds once every torrent is added and seeding. Run until SIGTERM, then shut down cleanly (the engine must send `stopped` to the tracker), write `shutdown_done` with elapsed seconds, exit 0.

### `--mode lifecycle`

`--fixtures DIR --index I --data-dir EMPTYDIR`: add torrent I as a fresh download into an empty dir, then run this script, writing a `step` line for each:

1. `added`. Wait until complete (the tracker gives it a seeder peer from a separate seed-mode harness). `completed`.
2. Sleep 45 s. `paused` (pause the torrent).
3. Sleep 45 s. `resumed`.
4. Sleep 45 s. `removed` (remove the torrent, keep data).
5. Sleep 10 s. `shutdown` (close the session cleanly), then exit.
